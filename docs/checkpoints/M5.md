# M5 — Learning loop v1

## Outcome

The first real Mattis learning loop is implemented:

1. A student creates a planned 25-, 45- or 60-minute session.
2. The browser uploads one to four images directly to the private Supabase bucket through a
   short-lived signed URL.
3. A vision-capable model transcribes and classifies the tasks without solving them.
4. The student reviews the detected task text before starting.
5. The planner allocates homework, repetition and summary time from the session duration, prior
   mastery and the last “next time” note.
6. The active task stays above one continuous tutor chat. A completed task advances to the next
   homework or repetition task.
7. Valid tutor evidence is restricted to the current task's concept keys, stored idempotently and
   folded into the mastery profile by a database trigger.
8. The final screen asks what the student should work on next time and stores the session summary.

## Privacy and integrity choices

- Image objects stay in a private bucket and are downloaded with the student's RLS-scoped JWT.
- Browser uploads go directly to Supabase Storage, so image bytes do not pass through a generic
  application upload endpoint.
- Tutor and parser calls request zero data retention at the gateway.
- Prompts and raw model responses are not copied into `ai_generations`.
- Mastery is derived from learning evidence; direct student mutation of mastery is revoked.
- Tutor retries use stable message IDs, and evidence is unique per tutor message and concept.
